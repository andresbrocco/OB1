# CONTEXT.md — Email History Import

## Purpose

Imports Gmail email history into Open Brain as searchable thoughts. Each email is cleaned, deduplicated via SHA-256 content fingerprint, embedded via OpenRouter, and stored in Supabase with sender, subject, date, and Gmail label metadata.

## Responsibility Boundaries

- **Owns**: Gmail OAuth2 token lifecycle (first-time browser consent flow + refresh), email body extraction and cleaning, noise filtering, ingestion into Open Brain thoughts table
- **Delegates to**: OpenRouter for embedding generation (`text-embedding-3-small`) and metadata extraction (`gpt-4o-mini`); Supabase REST API or a custom ingest Edge Function for persistence
- **Does not handle**: Scheduling or recurring sync (runs on demand); thread-level grouping; attachment processing

## Key Concepts

- **Sync log** (`sync-log.json`): A local file tracking ingested Gmail message IDs to prevent re-fetching on repeat runs. This is separate from the content fingerprint dedup — the sync log skips the Gmail API fetch entirely; the fingerprint check handles cases where the same content arrives through a different path.
- **Two-layer dedup**: (1) Local sync log by Gmail message ID avoids redundant API calls; (2) `content_fingerprint` column (SHA-256 of normalized content) in Supabase catches duplicates from other ingestion paths. The script gracefully degrades if the fingerprint column doesn't exist.
- **Ingestion modes**: Default mode writes directly to Supabase using `SUPABASE_SERVICE_ROLE_KEY` and calls OpenRouter inline. The `--ingest-endpoint` flag delegates all enrichment to a remote Edge Function (`INGEST_URL`/`INGEST_KEY`), which is the preferred mode when a shared ingest service is already deployed.
- **Noise filtering** (`isAutoGenerated`): Emails from no-reply addresses, transactional subjects (receipts, invoices, password resets), or bodies with excessive CSS blocks are silently dropped before embedding.
- **Body cleaning pipeline**: MIME multipart extraction → HTML-to-text stripping → quoted-reply removal → signature stripping → minimum word count gate (10 words).

## Non-Obvious Details

- The OAuth2 callback server listens on port 3847. This port must be free during first-time authorization and must match the redirect URI registered in Google Cloud Console.
- `credentials.json` and `token.json` are read from the same directory as the script (`SCRIPT_DIR`), not from the working directory. Running the script from a different directory will still find these files correctly.
- The rollback SQL (`rollback-chunking-columns.sql`) exists because an earlier version of this recipe added `parent_id`, `chunk_index`, and `full_text` columns to the `thoughts` table for RAG-style chunking. That approach was reverted in favor of truncation + fingerprinting (one thought per email). Users who applied the old schema need to run this SQL before re-importing.
- The `--window=all` option omits the date filter entirely from the Gmail query, which can result in very large fetches. The `--limit` flag (default 50) is the only guard.
- Embedding input is truncated to 8,000 characters before being sent to OpenRouter to stay within model context limits.
